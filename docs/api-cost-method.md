# API 成本估算方法

价格核对日期：2026-10-21。金额单位：美元（USD）。本页定义看板的两个 API 价格估算指标，均不代表 Codex 订阅账单、账号额度消耗或真实扣款。

## 两个指标分别回答什么

| 指标 | 含义 | 应如何阅读 |
| --- | --- | --- |
| 实测缓存 API 均价 | 沿用记录中的输入、输出和实际缓存命中量，套用公开 API 单价；因缓存写入量未保存，给出参考区间 | 是按实测用量重估的 API 价格区间，不是已核对的实际账单 |
| 全缓存乐观下界 | 假设全部输入都按缓存读取价收费，输出仍按输出价收费 | 是刻意乐观的价格下界，不代表所有输入真的可缓存，也不等于“所有可缓存输入都命中” |

两者使用相同的已发布样本范围和模型身份。只改变价格假设，不改变模型调用次数、实验结果或原始 token 记录。

## 单价与请求长度

采用 Standard API 价格，单位为美元 / 100 万 tokens。下表为单次请求输入不超过 272,000 tokens 时的单价。

| 模型 ID | 普通输入 pI | 缓存读取 pC | 30 分钟缓存写入 pW | 输出 pO |
| --- | ---: | ---: | ---: | ---: |
| gpt-6-astra | 10.00 | 1.00 | 12.50 | 50.00 |
| gpt-5.6-luna | 0.20 | 0.02 | 0.25 | 1.20 |

单次请求输入 **超过 272,000 tokens** 时，整次请求的普通输入、缓存读取和缓存写入单价乘以 2，输出单价乘以 1.5。阈值按请求判断，不能用整个episode或多个模型响应的累计输入直接判断。[Astra 模型说明](https://developers.openai.com/api/docs/models/gpt-6-astra) · [Luna 模型说明](https://developers.openai.com/api/docs/models/gpt-5.6-luna) · [API 价格表](https://developers.openai.com/api/docs/pricing)

本估算不使用 Batch、Flex、Fast 或其他速度档位，也不包括 12 小时缓存写入、区域附加费、税、工具调用、GPU、仿真或存储费用。采用的是核对日单价，不追溯还原运行当日的合同或促销价格。

## 指标一：实测缓存 API 均价

对每条可归属的用量记录 j，记总输入为 Ij、实际缓存读取为 Cj、输出为 Oj，未命中部分 Uj = Ij − Cj。缓存读取是总输入的子集，不再额外加到 Ij 上。

完整 API 输入费用需要区分普通输入、缓存读取和缓存写入；缓存写入与读取不重叠。当前公开历史记录没有保存足够的 `cache_write_tokens`，因此不虚构写入量。默认 30 分钟写入单价为普通输入价的 1.25 倍。[官方缓存计费说明](https://developers.openai.com/api/docs/guides/prompt-caching)

在已确定该请求价格档位后，对已知用量计算两个端点：

```text
参考下端 Lj = (Uj × pI + Cj × pC + Oj × pO) / 1,000,000
参考上端 Hj = (Uj × pW + Cj × pC + Oj × pO) / 1,000,000
平均参考区间 = [Σ Lj / N, Σ Hj / N]
```

下端把未命中部分全部按普通输入价计算；上端把它全部按 30 分钟写入价计算。两端是同一输入分区的不同假设，不能把普通输入费用和写入费用对同一token重复相加。

若一条累计记录包含多个模型响应，累计输入超过272,000却缺少逐请求分配，不能断言每次请求都进入长上下文档位。此时保留“全部按短请求价”至“全部按长请求价”的保守包络，并提示请求长度归属不确定。若累计输入不超过阈值，则其中各请求也不会超过阈值。

**用量不完整时，区间仅针对已知部分；右端不是整个实验实际费用的上界。** 尚未保存的usage仍未知，不按零补齐。缓存数或输入/输出拆分无法确定时，保留缺失提示，不用总token数猜测费用分区。

## 指标二：全缓存乐观下界

```text
乐观费用 Bj = (Ij × pC + Oj × pO) / 1,000,000
平均乐观下界 = Σ Bj / N
```

所有输入都假设按缓存读取价计费；忽略首次请求、新增输入和缓存写入所需的额外费用。已知长请求仍使用长上下文倍率；无法判定请求长度归属时，为保持乐观下界采用短请求价。存在未知usage时只累计已知部分。

本指标不利用实际 Cj 推断“理论可缓存量”。实际缓存命中可能受请求前缀、路由、时间间隔等影响，而首次输入和新增内容也不能仅凭累计usage判为可复用。因此，本指标用于显示一种统一、偏乐观的成本参照，不是缓存优化后必然能够达到的开销。

## 范围、分母与证据

- **N 是当前范围内已发布、去重后的结果样本数。** 这是每个样本的算术平均，不是每次API调用均价，也不是任务或能力宏平均。空范围显示“—”。
- **不按计划总数摊薄。** 发布1例就除以1，不除以42或111；尚未完整覆盖的首轮、Spiky-2或P50_111不能据此外推全套费用。实验卡片的当前范围也不自动等同固定评测范围。
- **重试与失败费用留在分子。** 包含已记录且归属于该范围的尝试；不因重试或无效历史尝试增加结果样本分母。LOW的两个额外无效尝试计费但不参与评分，也不增加N；它们只归属相应范围，不重复加入其他轮次。
- **模型分别计价。** Astra与Luna不能混用价格；多个模型参与同一episode时，应按已知模型身份分别计算后相加。未知或无价格映射的模型不静默套用其他模型单价。
- **观察与控制均计入。** Generation记录已包含观察模型与控制模型的已记录尝试，估算时不能再次追加一遍观察费用。
- **声明用量与收据验证分开。** 已接受补件中的声明usage可用于估算，但继续注明“含补件声明用量”；`accounting=known`不意味着收据身份已验证。
- **未知成本保持未知。** 有未记录usage时显示已知部分及缺失提示；不把缺失值当成零，不把参考区间当成完整账单置信区间。

## 论文可复用表述

为在统一价格口径下比较推理开销，我们根据已发布结果中的输入、输出及缓存读取token计数，采用2026年10月21日核对的OpenAI Standard API单价，报告两种按结果样本数计算的算术平均成本。第一种为实测缓存API价格参考区间：保留已记录的缓存读取量，将未命中输入分别按普通输入价和30分钟缓存写入价计费，以反映未保存缓存写入计数造成的不确定性；对无法由累计usage确定的长上下文请求归属，进一步保留短、长请求价格包络。第二种为全缓存乐观下界：假设全部输入按缓存读取价计费，输出按输出价计费，忽略首次输入、新增输入及缓存写入的额外开销。该下界不声称所有输入均可缓存，也不以实际缓存命中量替代理论可复用前缀量。成本分子包含范围内已记录的重试和无效尝试，分母仅计已发布的结果样本；这不是能力宏平均，也不对未完成的固定评测集合外推。存在未知usage时仅报告已知部分，参考区间的右端不构成完整实验成本上界；补件声明用量保留其证据标记。这些数值是公开API价格下的估算，不是Codex账单或账号额度度量，也不包含12小时缓存、特殊速度档位、税、工具、GPU或仿真费用。
